**Result: 8 out of 8 mapped reasons in `DEFAULT_KILL_TO_ECOA_MAP` are wrong.** This is the audit's most serious finding.

### Why this happened

Looking at the docstring at line 30-33 of `compliance.py`:
> "Full list is in Appendix A of Reg B (12 CFR 1002 Appendix A). These are the codes that map cleanly from v16 IMP-06 kill triggers."

The author **knew** there was a full list in Appendix A. They selected 5 codes thinking they mapped cleanly to the v16 kill triggers. But they confused the numbering:
- They labeled their "income insufficient" code as "19" — but Form C-1's "Income insufficient" is at code **08**, not 19.
- They labeled their "debt obligations" code as "21" — but Form C-1's "Bankruptcy" is at code 21. Their concept is at code **09**.
- They used "26" for loan amount — but per DSCR-specific extensions, 26 is LTV.

The T7 spec (`compliance_expansion_python_spec.md`) explicitly noted this in Sprint 1 ship docs:
> "Backwards compat aliases (Slice 1)
> ECOA_CODE_19_INCOME_INSUFFICIENT = "08"  # use code 08
> ECOA_CODE_21_DEBT_OBLIGATIONS_TOO_HIGH = "09"  # use code 09
> ECOA_CODE_26_LOAN_AMOUNT_EXCEEDS_MAX = "30"  # use code 30
> ECOA_CODE_27_COLLATERAL_INSUFFICIENT = "23"  # use code 23
> ECOA_CODE_28_PROPERTY_TYPE_UNACCEPTABLE = "29"  # use code 29"

So the **fix was documented but never coded**. Sprint 1 shipped pi_io, itia, reserves_check but skipped the compliance fix.
