## 1. EXECUTIVE SUMMARY

The DSCR Intelligence Platform addresses three confirmed market gaps—no multi-lender DSCR comparison, no integrated rent+DSCR platform, no optimization engine—in a market growing 50%+ YoY with ~$12-15B in annual DSCR originations (2024, projected $20B+ by 2026). Our GTM strategy leverages a freemium model targeting individual real estate investors as the wedge, expanding into mortgage brokers/LOs, and ultimately building a lender data & intelligence business.

| Metric | Value |

| TAM (Total Addressable Market) | $2.8B |
| SAM (Serviceable Addressable Market) | $420M |
| SOM (Serviceable Obtainable Market, Year 5) | $48M ARR |
| Year 1 ARR Target | $360K |
| Year 3 ARR Target | $6M |
| Year 5 ARR Target | $48M |
| Primary Revenue | SaaS subscriptions (65%) |

| Tertiary Revenue | Transaction/referral fees (10%) |
| Time to Breakeven | Month 28 |
| Time to $1M ARR | Month 18 |

**Strategic Thesis:** Free DSCR calculator captures the bottom of the funnel (investors actively shopping loans). The "aha moment" is seeing 3+ lender rates side-by-side—the moment they realize they've been overpaying. From there, upsell to optimization, portfolio analytics, and broker tools.

### 5.4 The "Aha Moment" — What Makes Users Pay

**Primary Aha Moment (Free → Pro):**
User enters their property, sees 3 lenders in free tier. The rate spread between lender A (7.25%) and lender C (7.75%) is shown—**that's $4,200 over 3 years on a $200K loan**. They want to see ALL 13 lenders. Paywall. They upgrade.

**Secondary Aha Moment (Pro → Premium):**
User with 4 properties runs sensitivity analysis and discovers their portfolio DSCR would jump from 1.05 to 1.20 by swapping one underperforming property. They want the Monte Carlo to stress-test this. They want the portfolio optimizer to find the optimal 3-property bundle. Paywall. They upgrade.

**Broker Aha Moment:**
Broker spends 3 hours manually calling 5 DSCR lenders for a client scenario. Next time, they enter the scenario once and get 13 lender quotes in 30 seconds. They generate a branded fee sheet in 1 click. They never go back to manual shopping.

| **Program Sponsorship** | $2K–$10K/mo per lender | $240K–$1.2M/yr | **MEDIUM** — Must be transparent |

### 7.2 Anti-Steering Compliance Framework

**The Problem:** RESPA Section 8 prohibits kickbacks for referrals. If we receive payment from Lender A and steer users to Lender A, that's a federal crime.

**The Solution — Neutral Platform Architecture:**

```
PRINCIPLE 1: Rate ranking is ALGORITHMIC, not commercial
├── Default sort: Lowest total cost (rate + fees + PPP)
├── User can re-sort by: rate, fees, DSCR requirement, LTV, closing speed
├── No lender can pay for higher organic ranking
└── "Sponsored" placements are clearly labeled and separated

PRINCIPLE 2: All qualifying lenders are shown
├── If a lender's program matches the user's scenario, it appears
├── No lender can pay to exclude a competitor
├── Missing lenders are flagged: "Lender X not shown — data unavailable"
└── Users can request addition of specific lenders

PRINCIPLE 3: Referral fees are STRUCTURED as data/technology fees
├── Lenders pay for API access and data products (not referrals)
├── Lead generation is structured as "advertising" (like Google Ads)
├── User explicitly opts in to lender contact (not auto-submitted)
└── All lender relationships disclosed on platform

PRINCIPLE 4: User choice is paramount
├── User selects which lender(s) to contact
├── Platform never auto-submits to a single lender
├── Comparison shows all options side-by-side
└── User can export data and contact lenders independently
```

### 7.3 Lead Generation Model (RESPA-Compliant)

**Model: Opt-In Marketplace (Not Referral Network)**

```
1. User runs DSCR comparison → sees 13 lender results
2. User clicks "Get Details" on Lender A and Lender C
3. Platform shows: "Share your contact info with these lenders?"
4. User OPTS IN → contact info sent to SELECTED lenders only
5. Lender pays per opt-in lead ($50-$500 based on quality)
6. User is notified: "Your info was shared with Lender A and Lender C"

This is LEGAL because:
- User initiates and controls the interaction
- Multiple lenders are always shown
- No single lender is favored
- User explicitly consents to sharing
- Fee is for the technology/service, not a "kickback"
```
